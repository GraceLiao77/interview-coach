现在这个 Step 4 是好时机吗？—— 部分是。

要看清 Step 4 到底训练什么。它主要是集成/胶水代码——调用外部 API、校验 JSON、控制成本。这确实是真正的后端工作，但它不是数据库/数据能力最深的地方。面试官很少问"你怎么调用 Claude API"，他们问的是数据建模、SQL、查询、事务、索引。

所以 Step 4 适合练后端架构能力，但这个项目里最有价值的数据能力在别处。诚实的地图如下：

我建议你从哪里开始手写（在 Step 4 里）

这些亲手写（不要让我生成）——它们对面试杠杆最高：

1. Answer + ScoreReport 的 Prisma 表结构——自己设计关系，决定哪些是列、哪些放 JSON，并自己加索引（@@index([answerId])）。面试官很爱问"你为什么给这个字段加索引？"
2. 一个事务——保存答案和它的评分报告时，用 prisma.$transaction([...]) 把两步包起来，避免只写了一半的脏数据。理解**原子性（atomicity）**是经典后端面试考点。
3. 错误处理 + HTTP 状态码映射——亲手写 try/catch → 400/404/429/500 的逻辑，搞清楚每个状态码为什么用。
4. 也自己写 SQL——挑 2~3 个 Prisma 查询，同时用原生 SQL 写一遍（prisma.$queryRaw 或在 Supabase SQL 编辑器里）。因为面试直接考 SQL，而 Prisma 把它藏起来了。

提升数据能力，单个价值最高的动作

把 Step 6 的一小块提前做。 "弱点画像"（"你最近 20 个回答里有 12 个漏了冠词"）本质上是一个 GROUP BY + 聚合 + 过滤的查询——正是数据面试要考的东西。自己设计并手写这个查询，然后在 Supabase 里跑 EXPLAIN ANALYZE，看查询计划、看你的索引有没有被用上。这一个练习教给你的面试相关数据能力，比 Step 4 全部 API 代码还多。

我的总建议

把 Step 4 做完（它搭出你需要的流水线），但把这四项当成亲手写、不用 AI 的练习：表结构+索引、事务、错误/状态码映射、以及查询的原生 SQL 版本。然后尽早优先做 Step 6——那是你的数据能力金矿。
